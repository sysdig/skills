# Onboarding Summary Artifact

After verification (Step 8) — or after generating configuration on the
config-only path (no deploy; see the "Config-only path" subsection in
`SKILL.md`) — generate a summary artifact in both Markdown and HTML formats.
This gives the user a tangible deliverable they can share with their team or
archive.

## Markdown Template

Write `onboarding-summary.md` to the working directory using this structure:

```markdown
# Sysdig onboarding summary

| Field | Value |
|-------|-------|
| Date | {{DATE}} |
| Status | {{STATUS — a short plain sentence describing the outcome; e.g. "Applied and verified" or, on the config-only path, "config-only — Terraform written and validated offline (terraform validate); not applied (AWS credentials missing); apply from CI/CD"}} |
| Provider | {{PROVIDER}} |
| Scope | {{SCOPE}} |
| Account/Project ID | {{CLOUD_ACCOUNT_ID}} |
| Sysdig Region | {{SYSDIG_REGION}} |
| Sysdig Secure URL | {{SYSDIG_SECURE_URL}} |

## Capabilities enabled

{{CAPABILITIES_LIST — bullet list of enabled capabilities with brief description}}

## Resources created

{{IF config-only path: REPLACE this whole section with a "Next steps — apply"
section (see Config-only path below) — no resources exist yet.}}

{{RESOURCE_COUNT}} resources managed by Terraform ({{STATE_ENTRY_COUNT}} total
entries in state including data sources):

\`\`\`
{{TERRAFORM_STATE_LIST — output of `terraform state list`, filtered to exclude
data.* entries. Use: terraform state list | grep -v '^data\.'}}
\`\`\`

## Sysdig links

{{IF config-only path: these links resolve only after the config is applied —
render them under an "Available after apply" note rather than as live links.}}

- [Cloud Accounts]({{CLOUD_ACCOUNTS_URL}}) — Check connection status
- [Inventory]({{INVENTORY_URL}}) — Browse cloud asset inventory
{{IF CDR: - [Events]({{EVENTS_URL}}) — View security events (last 24h)}}

## Terraform configuration

\`\`\`hcl
{{MAIN_TF_CONTENT — the generated main.tf file contents}}
\`\`\`

---
Generated by Sysdig Onboarding Assistant
```

## Config-only path

When the summary is produced on the config-only path (config generated but not
applied), the `Status` field carries the free-text status sentence — and must
convey the four facts in [session-logging.md](session-logging.md) (what was
generated, what was validated or why not, what was not done and why, the next
step / owner). Then:

- Replace **Resources Created** with a **Next steps — apply** section: the
  handoff runbook listing the commands the next persona or pipeline must run and
  every value they must supply (the `Parameterized` / `User-supplied` recap
  values from confirmation-flow.md).
- Note that the **Sysdig Links** resolve only once the config is applied.

## HTML Generation

After writing the Markdown file, generate `onboarding-summary.html` by
converting the Markdown to a self-contained, Sysdig-branded HTML page with no
external dependencies:

1. Read the Markdown content you just wrote (you have it in memory from
   generating it — do NOT re-read the file).
2. Read [`sysdig-brand.md`](sysdig-brand.md) and copy its `<style>` block into
   the `<head>` **verbatim**, and its brand-header snippet as the first child of
   `<body>`. Do not invent or hardcode colors — the brand file is the single
   source of truth, and it handles light/dark mode automatically.
3. Write the HTML file using the structure below.

Use this HTML structure:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Sysdig Onboarding Summary</title>
  {{STYLE_BLOCK — the <style>...</style> block copied verbatim from sysdig-brand.md}}
</head>
<body>
  {{BRAND_HEADER — the <div class="sd-header"> snippet from sysdig-brand.md}}
  {{HTML_CONTENT — convert Markdown sections to HTML tags:
    - # → <h1>, ## → <h2>
    - table → <table> with <th>/<td>
    - bullet lists → <ul><li>
    - fenced code blocks → <pre><code>
    - links → <a href="...">
  }}
  {{POWERED_BY — the <div class="sd-poweredby"> snippet from sysdig-brand.md, as the last element}}
</body>
</html>
```

The HTML conversion does NOT need to be a generic Markdown parser. Since you
are generating both the Markdown and the HTML, produce the HTML directly from
the same data you used for the Markdown. Write both files in sequence.

## Rules

- Write both files to the working directory (same directory as the Terraform files).
- The Terraform configuration in the artifact is the **generated** `.tf` file
  content — you already have it in memory from Step 7. Do NOT re-read `.tf`
  files from disk.
- Resource list comes from `terraform state list` output captured during
  Step 8 verification.
- Do NOT include any secrets, tokens, or sensitive values in the artifact.
- If file writes are denied by the user, present the Markdown content in a
  code block.
